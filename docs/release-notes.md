# Release notes

## Native text snapshot and deterministic checker (A1)

Added `captureWorkspaceText` in `src/native-work.ts`, reusing the existing single-handle bounded UTF-8 read. It issues a frozen `{captureId,file,text}` snapshot that retains a leading BOM, CRLF and Unicode without trimming or normalization; byte count and SHA-256 come from the same read buffer. `observeWorkspaceFile` keeps its signature and its four plain file facts without text or capture id. The new `src/native-snapshot-checker.ts` is a synchronous leaf with fixed condition kinds `text-includes`, `json-valid`, `json-type` and `json-equals`, strict bounded plan shape, bounded JSON pointers, a 16 KiB full-plan cap including the digest and a 32 KiB receipt cap. It accepts only locally issued frozen snapshots and plans, parses captured JSON with `JSON.parse` semantics (duplicate keys last-wins, BOM not stripped), and returns condition facts with `taskAccepted:false` and `semanticAcceptance:"not-evaluated"`.

Issuance and exact-plan binding are process-local object identity, not permission or provenance. `matchesNativeTextCheckReceipt` compares historical objects only: an old snapshot still matches its receipt after file changes, while a new capture of equal bytes does not. The checker performs no filesystem, process or model call and adds no A2 child consumer, live-work association, store, entry, CLI command, permission or semantic coverage; it is a building block, not a complete versioned handoff feature. An independent static review found and the patch fixed exact-plan binding, error bounds, plan-shape ingress and the full-plan size cap. Final `bun run check` passed type checking, 768 unit tests (41 files, 34,524 assertions) and 15 human-review simulations. Nine new focused tests cover real one-read BOM/Unicode/CRLF/empty text, source changes, V1→V2 and ABA rejection, and forged/accessor/proxy/shape/size/pointer/limit cases. No actual host run covered A1, and no entry or default policy changed.

## Optional selected instance result report (C2)

Added an optional, strict `report.instanceResult` selector `{instanceId,parentToolCallId,envelopeSha256}` to the opt-in instance entry's existing `agent_work` report path. `inspect.instanceResults` exposes bounded inspection-time candidates (at most 64 rows and 64 KiB encoded, with `total`/`omitted`/`complete`; whole-catalog failure has empty rows and `null` counts). The selector must be copied from a currently visible available row, and its parent `task` call must also be selected in `checks`. The ordinary native entry has no catalog and refuses an explicit selection; ordinary reports, the default daily entry and default policy are unchanged.

`src/native-entry.ts` remains the sole report validator, file reader, publisher and replay owner. The composed instance port resolves the exact root, record, original work reference and frozen C1 observation. Publication requires a complete known completed envelope, verified Role/Skill gates, live work/session/workspace/root/token context, zero pending or dropped ingress and a current parent task call; abort, lifecycle failure, conflict, sticky observer error or stale work refuses. Actual signal/host checks run before and after awaited file reads; a final synchronous refresh and pure revalidation precede publication. Replay returns the historical receipt without rereading files after revalidating the selection and work.

The report output `instanceResult` records the original association/work/envelope facts plus `artifactBasis:"observed-during-report"` and `semanticAcceptance:"not-evaluated"`. Output bytes are those read during the report, not the child's original delivery, exclusive authorship, a commit-time or atomic multi-file snapshot, meaningful check coverage or semantic acceptance. ## Native instance result and work observation

The newer C2 section above adds a selected-report publication and report-time association gate, not artifact acceptance. The 64 KiB status response may omit details; it is not a total heap or record bound. This changes no default entry, settings, model, tool set or scheduler behavior. ## Continuous task core and exact task guards (B3-A)

History is not durable cross-process recovery.

`agent_task revise` and `cancel` now require `expectedTaskId` together with `expectedTaskRevision`, and `inspect` may use the same pair to read one visible retained task. `agent_job submit` and `query` require the same exact selector; a query checks it before lookup or transport. Shared owner admission and `admitPublishedTask` accept only immutable task id+revision guards, freeze committed admission facts, and revoke an admission if notification changes the current task without undoing the committed count. Task-specific owner events route by task id.

A host-generated task id that is already retained is rejected before any commit instead of overwriting the old task. Authority resolution returns a candidate anchor without mutating the live grant; the resolved anchor is written only in the atomic commit after every callback and a pure final state/id/capacity check. The entry rechecks that its captured owner is still the published owner after actual context getters, audit and preflight, so a late replacement cannot mutate or disclose the old owner. Shared admission additionally revalidates final branch reachability and any newly created acceptance reservation before the consumer acts. Job submit and query run their exact-target, status, binding, reservation and hazard check after the last host clock/record callback and immediately before transport; a refused dispatch keeps honest `not_dispatched` facts and the committed task admission.

Capacity, guard, replay and preflight failures leave the prior current task, grants, counters and indexes intact; postcommit notification failures preserve committed identity. Unknown acceptance-installation hazards still block starting another task and are never converted into a terminal state. Automatic v1 and human/hybrid v2 record semantics are unchanged. This increment does not add a daily entry, package-default switch, durable recovery, historical delivered-file retrieval (B3-B), or a real OMP/model journey (B3-C); genuine human review remains deferred to the completed personal trial.
