# Release notes

## Controller-owned existing-run inspection (R2-C1b1)

R2-C1b1 adds only a bounded host-only readonly inspection of one existing original Harness run under its own Store lease. It is not recovery, resume eligibility, cancellation, a full leased current-intent/observation join, stop proof, accounting continuation or a product pass. This increment builds on published base `598bef11638dacb50a2aa7a7b7ebe821fc11f20d`; publication is handled separately. `NativeHarnessBackendHost.inspectExisting?` remains optional so existing host fakes remain valid, while `createNativeHarnessBackend` always supplies the actual method. No entry, tool, run creation, prepared root, worker or provider call is added.

The target is an exact own-data locator `{runId, ownerId, selectorSha256, preparedRelativeRoot}`: lowercase UUIDs, 64 lowercase hex characters and an `omp-harness-` root plus six ASCII alphanumerics. This reuses the actual B2-supported locator without changing the broader persistence or source format. The control is an exact own-data `{signal, guard}` with an actual intrinsic `AbortSignal` and a synchronous `undefined`-returning guard. Target, context `cwd`, control and host configuration are copied before the first await, and the storage/prepared/workspace/store/source directories are validated as actual non-link directories. A post-call mutation cannot retarget an in-flight inspection.

`HarnessController` now captures one own-data `recoveryInspector` at construction, acquires the original Store's `acquireWithContext` exactly once, and exposes only a frozen `{runId, ownerSha256, assertCurrent}` view. No lease handle, token, Store, record or commit is exposed, and the view refuses after release. The inspector may return `void` or one ordinary same-realm `Promise<void>`; settlement uses the captured intrinsic `then`. Subclasses, custom or cross-realm prototypes, own `then`/`constructor`, shadowed accessors and foreign thenables are refused before inherited species/accessor lookup or a foreign `then` call. The lease is released in `finally` even on inspector failure or rejection; the callback protocol does not defend against general mutation of the realm's `Promise.prototype`.

Under the lease the fixed backend observer directly runs the existing B2 two-pass lifecycle with the actual signal and clock. It requires two controller-owner rounds equal to `view.ownerSha256`, eight primary captures with an opened file, settled successful close and matching second pass, stable final pins, two live lifecycle rounds, complete or valid zero-attempt coverage, and compatible metadata/run/source/prepared/store/build identity. A present own controller PID is expected diagnostic data; older-worker presence or unknown state is readonly, not stopped proof. If B2 stops before the lifecycle phase, inspection refuses with a specific bounded reason because owner proof is unavailable; it never fabricates owner proof or reads a substitute owner.

After the Controller releases the lease, the host guard and actual signal are checked, a finite nonbackward clock must remain within the original B2 window, the wire is frozen, and the actual signal is checked again after the clock and wire. Success is `{ok:true, diagnostic:{schema:"omp-agent.native-harness-existing-inspection.v1", readOnly:true, resumeAvailable:false, runId, leaseOwnerSha256, observation}}`, bounded to 128 KiB of UTF-8 JSON including the wrapper. Failure is a bounded `{ok:false, reason}` of at most 320 printable ASCII characters with no diagnostic. The result carries no JSON permission or token and establishes no host identity, current native work, session authorization, stop proof or resume eligibility.

The only filesystem effect is the original run-lock acquire/release lifecycle. There is no new run, dispatch inventory, accounting owner, reserve, claim, conditional interrupted commit, cancel, execute, resume or worker. Marked execute and resume gates remain closed, and a historical diagnostic is never continuation authority. Acquisition retains the legacy initial read/regular-file validation; not every Store read is bounded and no hard whole-call timeout is claimed. The existing B2 30-second soft and 5-second lifecycle windows are unchanged, and lease acquisition/release may stall. Zero-attempt/no-snapshot `not-required` content does not verify initial prepared inputs; C1b2 must add the original eight files with 256 KiB per-file and 256 KiB total bounds. No actual cross-parent worker stop, provider/model run, semantic quality, recovered completion provenance or recovery acceptance is claimed.

## Same-owner accounting continuation foundations (R2-C2a)

R2-C2a adds only an explicit fresh V2 accounting-owner storage and bounded continuation foundation; it is not runtime recovery, resume eligibility, current-intent/lease integration or a product pass. The default session creator still creates V1 and ordinary V1 behavior is unchanged. New `createNativeHarnessRecoveryAccountingOwner` creates a fresh V2 primary for the supplied owner identity; later continuation retains that same owner. It uses the same owner path, directory pins, short write lock, atomic writer, complete same-revision CAS and post-write poison rules. An existing owner directory, including V1, is refused; no existing V1 owner is reused, upgraded or mutated. There is no default switch, runtime owner association, renewed admission, budget or deadline. Generic open, observe and decode expose a strict discriminated V1|V2 checkpoint; V1 refuses all three continuation actions without mutation, and an already-stored V2 primary keeps its V2 methods.

V2 admissions add immutable `preparedRevision` and `runRevision` bindings, and the original settlement is write-once and refused after the first continuation claim. Replay requires exactly one globally unique owned revision for every original reserve/prepare/run/settle/block action and every appended claim, finish and cost observation; revisions must be contiguous, so a prefix cannot see a future binding or settlement. Limits are 8 claims, 8 finishes, 64 cost observations, 80 events, 145 full actions, 16 admissions and 64 KiB. Every checked prefix and candidate additionally reserves 512 B for each missing event slot, 256 B for each null original settlement, 256 B while the block is empty and 64 B format headroom. This covers the whole transition encoding, including indentation, commas and revision width; no fake receipts are serialized. Future bind sizes are still checked, and the finite tail does not promise unlimited late events. A full cost cap refuses new reserves and claims while a permitted finish and an exact duplicate acknowledgement can still proceed; future C2b must gate every worker dispatch against remaining event capacity.

Each admission keeps its original allocation and one cumulative observed highwater. Occupancy is shared, not multiplied: a claim that still holds occupancy transfers it, and a claim after release must reacquire free concurrency. A known outcome writes the observed highwater and releases its reservation; a later claim may re-cover only the original allocation minus that highwater within the current lifetime total. Unknown usage keeps the single original allocation sticky with no refund. A first claim before the original settlement and a claim that supersedes an unfinished generation remain conservatively unknown. A finish is accepted once for the latest open generation; a stale-generation finish or an original settlement after the first claim refuses, while late original or old-generation cost facts remain bookable. Observations raise the cumulative highwater by raw maximum, with rounding only in projection, so sub-nanodollar facts accumulate before rounding. An exact same observation ID and whole fact on the current CAS acknowledges without a write, hook or revision; stale CAS or a changed fact refuses. Worker overspend, per-run excess, owner lifetime excess and the stored original block are sticky. Costs and finishes may still book after the original admission deadline or a sticky block; new reserves and claims refuse a sticky financial block. A claim's `claimedAt` data must remain inside its original admission window, and this leaf does not read the actual current clock; actual currentness remains a future host join. Stored deadlines are data, not current execution authority.

No schema field or identifier grants lease, current-intent, stop or dispatch authority. This increment adds no actual backend/Controller/Slot continuation, recovered completion provenance, runtime/current-intent/lease join, resume or default behavior change.

## Guarded recovery lease and cancellation foundations (R2-C1a)

R2-C1a adds a bounded Store lease, marked cancel-generation and conditional interrupted-state foundation; it is not recovery, resume eligibility, a leased current-intent/observation join, stop proof or accounting continuation. The original `RunStore.acquireWithContext` reuses the original lock algorithm, and `acquire` remains the release-wrapper compatibility path. A frozen Store/run-bound context in an internal `WeakMap` exposes only `ownerSha256`, `assertCurrent` and `release`, with no public token. Owner bytes are the original pretty JSON plus LF, and the same string is hashed and written. Copies, lookalikes, foreign Store/run and released contexts refuse; busy commit or release conflicts. Root and run are captured before the first await, and new commit and marked cancel keep the captured target after a runtime `store.root` change. Same PID alone is not authority; known-dead stale-owner handling is original, while missing or initializing locks refuse.

Owner, cancel and conditional-primary reads are bounded at 16 KiB, 64 B and 256 KiB before allocation and the actual read, with post-read `fstat`, one actual close and pathname checks; final lease checks cover root, run, lock and active state. Initialization cleanup and release preserve observed replacements. These are finite checks under the original cooperating-lock protocol, not OS-atomic check/delete or adversarial external-replacement guarantees. Initial acquire retains the original legacy run validation, so not every original Store read became bounded. Marked cancel writes a fresh fixed ASCII `cancel:<uuid>` plus LF generation (44 B) for every accepted request, including cancelled; completed/applied no-op; malformed, oversized or unsafe markers refuse with no silent EEXIST coalescing. Unmarked cancel and all runtime entry/profile/default behavior remain unchanged.

Store-only `commitRecoveryInterrupted` requires an actual issued lease, expected raw-primary SHA-256 plus revision and identity, cancel-generation SHA-256 or confirmed absence, the original immutable origin, a real intrinsic `AbortSignal`, a safe positive monotone clock at `min(original seed outer deadline, createdAt + inner duration)` and a trusted host assertion. Inputs and target are captured; the callback is not JSON approval, stop proof or accounting proof. Under the same original short lock, the existing already-locked CAS/save body avoids a nested lock: backup/primary then exact matched cancel consumption and directory sync. Task/config/snapshot/stages/costs/reservations/`createdAt` are preserved; only the existing revision/status/`updatedAt` advance, and the serialized record stays 256 KiB. Bounded guards follow async work, and exact raw/identity rereads precede publication. The final host, primary, lease and currentness checks run inside the write-lock callback before the short lock is released; after the helper's awaited release, only one synchronous intrinsic-signal plus monotone-deadline seal runs. No post-release async host, lease or primary check is claimed. A newer cancel after commit remains persisted.

A before-save failure leaves the cancel generation. A failure after save/cancel clear/sync/lock release/currentness is an actual partial-state failure with disk changes retained; there is no rollback, retry, execution success, cross-file atomic transaction or hard IO-deadline claim. An observed signal/clock change prevents later publication or clear when observed and grants no future permission. Marked `Controller.resume` refuses inside the original lease before clear/save/dispatch; marked execute keeps only the original initial `queued`/revision 0/empty stages/no snapshot path, with completed/applied non-executing returns, so noninitial execute cannot bypass the gate. Unmarked behavior and the actual marked initial path are retained. This primitive is not connected to guarded continuation, accounting, C1b/C2, current work, user intent or stop proof, and adds no model tool/entry/work reference.

Inventory maps only an actual pre-write `StoreConflictError` to `NativeHarnessDispatchInventoryError` `changed` with cause; other pre-write errors and post-write ambiguous/poison behavior are unchanged. Replacement preservation remains tested; the generic message does not assert a replacement exists. The vendor `sourceId` is `194f9801d9262d0194bd7075aa9d47d91bdeddb756791841687eb16162223072`; original upstream/base/licensing are unchanged. The label is build compatibility, not executable authentication or cross-build migration; the existing B2 label join is distinct from future C1b leased current-intent wiring, and C1a does not implement that join.

## Bounded original recovery file observation (R2-B2b)

R2-B2b adds a host-only readonly double observation of the four original native recovery primaries: `run.json`, `recovery-source.json`, `dispatch-inventory.json` and `accounting-owners/<selectorSha256>/owner.json`. `observeNativeHarnessReconciliationFiles` in `src/native-harness-reconciliation-files.ts` reuses the existing `captureWorkspaceText` byte reader and the B2a pure metadata join. It adds no ledger or controller, default entry/tool wiring, lock, cancel marker, process or artifact inspection, or resume authority; it starts no worker, model, network or process query. The four fixed paths are read twice in fixed order with no backup fallback.

One call is bounded to eight captures (four primaries twice), 1,212,416 charged cap bytes including refused captures, one concurrently opened file and seven pinned parent directories. Caps are 256 KiB for run, 16 KiB for source, 256 KiB for inventory and 64 KiB for owner, charged before each capture. Public capture summaries expose SHA-256 and bytes but not dev/ino/mtime/ctime; the collector internally retains and compares the actual opened-file dev/ino/size/mtime/ctime signature, and completion requires SHA-256, that signature, the complete first and second bytes and final directory identity to agree. Same-revision byte change and identical bytes at a new inode are refused, and any mismatch or refusal stops later captures. Per-file lstat and opened-handle stat check the cap before allocation/read; opens use the no-follow flag plus `O_NONBLOCK` when available, with a regular-file check.

Close facts are explicit attempted/settled/succeeded. A rejected close, including rejection with `null` or `undefined`, cannot yield stable facts; a post-open refusal closes the actual acquired handle; held original IO remains pending until its actual settlement, with no `Promise.race` drain claim. One 5,000 ms soft observation deadline is fixed at start, and a backward clock is refused. Ordinary IO checks clock and actual signal around actual settlement, including rejection. Exact exception: the pre-open fixed seven-parent seal (at most 14 metadata awaits) plus open is one observed operation; only actual-signal checks run inside the seal and synchronously after the helper, with the caller clock sampled before the seal and after open, so not every seal await samples the deadline. If the post-open guard detects expiry, that newly acquired handle is closed before its first byte read and no later capture starts; expiry detected after an earlier read cannot retroactively promise zero bytes. Real IO/cleanup may exceed 5 s. This is not a hard-kernel deadline, atomic `openat` or an ABA solution.

`status:"stable"` is independent of `metadata.compatible`; stable files with incompatible metadata report `status:"stable"` and `metadataStatus:"incompatible"`. The result is a frozen bounded summary with no raw text, handles or permissions, `resumeAvailable:false`, and `processes`/`artifacts` `not-inspected`.
